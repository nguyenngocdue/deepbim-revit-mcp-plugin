# MSI Installer Build / Export

## Scope

The installer is built from the plugin workspace, but it packages files from two workspaces:

```text
E:\C# Tool Revit\revit-mcp\
├── mcp-addin\revit-mcp-plugin\     ← Revit add-in + WiX installer project
└── revit-mcp-server\               ← Node/TypeScript MCP server packaged into MSI
```

## Primary Command

Run from `revit-mcp-plugin/`:

```powershell
.\scripts\Build-OneMsi.ps1 -RevitVersion 2024 -ProductVersion 3.0.0
```

`Build-OneMsi.ps1` is the preferred one-version wrapper. It builds the Revit add-in payload first, verifies required files under `plugin\bin\AddIn {version} Release\`, then calls the WiX MSI builder.

Common variants:

```powershell
.\scripts\Build-OneMsi.ps1 -RevitVersion 2026 -ProductVersion 3.0.0
.\scripts\Build-OneMsi.ps1 -RevitVersion 2025 -ProductVersion 3.0.0
.\scripts\Build-OneMsi.ps1 -RevitVersion 2024 -ProductVersion 3.0.0 -SkipPluginBuild
```

Final MSI is copied to:

```text
installers\msi\output\DeepBimMCP-Revit{version}-v{productVersion}.msi
```

WiX also writes the build output under:

```text
installers\msi\bin\Release\
```

## Build Flow

For a single version, `Build-OneMsi.ps1` is responsible for the full build/export flow:

1. Build the add-in payload with `Build-RevitVersions.ps1 -Versions {version} -Configuration Release`.
2. Verify required add-in files under `plugin\bin\AddIn {version} Release\`.
3. Call `installers\msi\Build-Installer.ps1 -Versions {version} -ProductVersion {productVersion}`.

`Build-Installer.ps1` is the lower-level MSI packaging script. It:

1. Resolves target Revit versions from `-Versions` or `RevitVersions.json`.
2. Locates the server project at `..\..\..\revit-mcp-server` from the plugin root.
3. Stages production Node dependencies into `installers\msi\obj\server-prod-npm\`.
4. Generates WiX fragments from the current server payload:
   - `ServerFiles.wxs` from `revit-mcp-server\build`
   - `ServerNodeModules.wxs` from staged production `node_modules`
   - `ServerPublic.wxs` from `revit-mcp-server\public`
   - `ServerViews.wxs` from `revit-mcp-server\views`
5. Builds `DeepBimMCP.Installer.wixproj` once per Revit version.
6. Copies the resulting `.msi` into `installers\msi\output\`.

Do not package pnpm's live `revit-mcp-server\node_modules` directly. It may contain symlinks that WiX cannot bind reliably. Use the staged npm production dependency folder generated by `Build-Installer.ps1`.

## WiX Project

`DeepBimMCP.Installer.wixproj` must define these WiX preprocessor constants:

| Constant | Purpose |
|----------|---------|
| `ProductVersion` | MSI product version |
| `RevitVersion` | Target Revit year, e.g. `2024` |
| `PluginBinDir` | Built add-in payload, e.g. `plugin\bin\AddIn 2024 Release` |
| `ServerSrcDir` | Server project root, `revit-mcp-server` |
| `ServerBuildDir` | Server compiled JS, `revit-mcp-server\build` |
| `ServerNodeModulesDir` | Staged production `node_modules` |
| `ServerPublicDir` | Server static assets, `revit-mcp-server\public` |
| `ServerViewsDir` | Server HTML views, `revit-mcp-server\views` |

If `ServerPublic.wxs` or `ServerViews.wxs` references `$(var.ServerPublicDir)` or `$(var.ServerViewsDir)`, those constants must be present in `DefineConstants`.

The MSI installs server files under `ProgramFiles64Folder`, so the WiX project must build as x64:

```xml
<InstallerPlatform>x64</InstallerPlatform>
```

The add-in files intentionally install under the current user's Revit add-in folder:

```text
%APPDATA%\Autodesk\Revit\Addins\{year}\
```

Because this is a per-user Revit add-in layout, ICE38/ICE64 validation checks may be suppressed in the WiX project.

## Product Feature Payload

`Product.wxs` must include all generated server component groups in `ProductFeature`:

```xml
<ComponentGroupRef Id="ServerBuildFiles" />
<ComponentGroupRef Id="ServerNodeModulesFiles" />
<ComponentGroupRef Id="ServerPublicFiles" />
<ComponentGroupRef Id="ServerViewsFiles" />
```

The generated fragments own the installer subdirectories under `DIR_Server`:

| Fragment | Directory root |
|----------|----------------|
| `ServerFiles.wxs` | `DIR_Server_build` / `build` |
| `ServerNodeModules.wxs` | `DIR_Server_node_modules` / `node_modules` |
| `ServerPublic.wxs` | `DIR_Server_public` / `public` |
| `ServerViews.wxs` | `DIR_Server_views` / `views` |

Do not also declare those same directory IDs manually in `Product.wxs`, or WiX will fail with duplicate directory identifier errors.

## Revit 2024 Packaging Note

Revit 2024 uses the `net48` add-in payload. The 2025+ output may include .NET/Windows SDK runtime files such as:

```text
WinRT.Runtime.dll
Microsoft.Windows.SDK.NET.dll
```

Those files are not always present in the Revit 2024 payload. In `Product.wxs`, include them only for versions that actually produce them.
